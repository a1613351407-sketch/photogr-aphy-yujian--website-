# 玉鉴 PHOTO STUDIO

摄影师的拍摄前问卷网站。首页提供四步问卷，摄影师通过 `/studio` 查看提交。

- 三张内置 ImageGen 风格示例：小清新、个性人像、情绪人像。素材与完整生成提示词位于 `public/images/`。
- 风格单选，支持自定义风格、拍摄用途、场景、修图、妆造、日期、预算、沟通备注；完成必答选择后自动进入下一步。
- 最多 6 张 JPG / PNG / WebP 参考照片，单张 5 MB、总计 12 MB。服务端校验实际文件签名。
- 问卷保存在 D1，照片保存在 R2。照片读取与问卷列表均要求摄影师会话；客户之间无法查看资料。
- `/studio` 支持查看、标记已联系、导出沟通单、打开原始参考图片，以及单条或批量删除沟通记录。删除会同时清理网站保存的参考照片和发送记录，不会撤回已经发到邮箱或飞书的文件。
- `STUDIO_SECRET` 是摄影师登录口令，必须作为服务端 Secret 配置，不能放进前端。生产环境通过 Sites 管理；本地通过未入库的 `.dev.vars` 配置。
- 登录使用 HttpOnly、SameSite=Strict 会话 Cookie，HTTPS 下设置 Secure。会话有效期 8 小时；提交与登录有服务端频率限制。
- 此版本的 AI 图片是预先生成的风格示意，没有向客户照片调用生成模型。

## 本地开发

使用 Node.js 22.13+，执行 `npm install` 和 `npm run dev`。数据库迁移在 `drizzle/`，由 Sites 在线部署时应用。本地测试需通过 Wrangler 对本地 DB 应用迁移。

## 检查

`npx tsc --noEmit`、`npm run build`。`scripts/smoke-test.mjs` 对 localhost:3000 检查问卷校验、真实照片上传与读取、工作台认证及状态保存，只生成本地测试数据。该脚本从 `.env` 读取本地测试口令，不输出口令。

网站对外分享之前，需要在 Sites 将访问范围开放给客户。摄影师工作台仍需专属口令。

## 邮件发送

客户提交后，问卷与参考照片先保存，邮件发送记录与问卷在同一个数据库事务中写入。随后可通过 Resend HTTPS API 向部署时配置的收件人发送文字沟通单及所有参考照片附件。公开源码仅包含示例地址，不包含真实收件邮箱。

所需服务端环境变量：

- `RESEND_API_KEY`：Resend 发送密钥，建议仅授予发送权限。
- `EMAIL_FROM`：Resend 已验证域名下的发件地址，例如 `玉鉴 PHOTO STUDIO <photo@你的域名>`。

生产值须设置在 Sites 环境变量中；密钥应标记为 Secret。没有邮件授权时，提交仍成功保存，邮件保持待发送，工作台明确提示未授权。配置好后可对待发送记录点击“发送 / 重试”。原有问卷不会被自动补发。

每封邮件使用问卷 UUID 作为固定幂等键；自动重试最多两次，超过 23 小时后拒绝不确定发送记录的重试，以免越过服务的 24 小时去重窗口。发送成功表示邮件服务已接收，不能据此断言已进入 Gmail 收件箱。必须在真实配置后另行验证实际投递。

`node scripts/email-test.mjs` 使用模拟传输校验中文内容、固定收件人、附件字节、幂等载荷及失败处理，不会发送实际邮件。`scripts/smoke-test.mjs` 还验证无发信授权时的持久保存和错误提示。

## 飞书私聊文件同步

通过企业自建应用机器人，把文字沟通单与每张参考照片作为文件发给摄影师本人。所需服务端配置为 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`FEISHU_RECEIVE_ID`，以及 `FEISHU_RECEIVE_ID_TYPE`（默认 `open_id`，也可使用 `user_id` / `union_id`）。接收人标识必须属于对应应用可访问的用户。

飞书应用需要启用机器人能力，并开通 `im:resource` 与 `im:message:send_as_bot` 权限。建议使用摄影师在该应用下的 `open_id`，并先在飞书里打开与机器人的私聊，让机器人具备私聊触达关系。

每个文件独立记录上传 file_key、消息 message_id 和发送状态。重试会跳过已成功的文件，复用已上传文件及固定 UUID；对可能已被飞书接受的请求仅允许 55 分钟内重试，避免越过飞书的一小时去重窗口。机器人授权失败不会影响问卷、照片和邮件发送记录的保存。此功能只新发消息，不修改或覆盖飞书原有内容。

`node scripts/feishu-test.mjs` 通过模拟传输验证正式 API 请求格式、原始附件字节、接收人、消息 UUID 和错误处理，不会向飞书发送消息。上线前仍需配置机器人权限与接收人，并真实验证私聊中的文件。

待填配置集中在项目外的 `通知发送配置.env`。该文件不要纳入网站源码。实际授权信息缺失时，界面应保持“尚未授权”，不能声称已发送。
